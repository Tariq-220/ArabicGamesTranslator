# معالجة تراجع الرسائل في 0.5.8

أبلغ المستخدم أن الجوال والتنبيهات لا يظهران رغم وجود قراءة، وأن آخر سطر يدخل الحوار وتظهر قراءة داكنة قرب الخريطة. يوجد تأخير رغم التسريع. المقطع Snapchat-60190528.mp4 يتجاوز حد أداة التنزيل (32 MiB)، ولم تتم مشاهدته؛ لا يُنسب إليه تحليل بصري. الوصف والسورس أساس التحقيق الحالي، والسجل السابق متاح دون إعادة تحليله.

## أسباب مؤكدة من السورس

- شرط نشر 0.5.8 يتطلب جاهزية كل أجسام رسائل الصفحة: خلية فارغة واحدة تحجب كل النتائج السليمة.
- تجديد البطاقات يستثني التنبيهات، ويشترط اكتمال الصفحة للجوال. لذلك تنتهي مدة النتائج الجزئية/التنبيه مع بقاء المصدر.
- ملكية الرسائل مشروطة بتطابق النص حرفيًا تقريبًا؛ القراءة المختلفة للفقاعة نفسها قد تدخل الحوار أو بطاقة أخرى.
- طابور المحرك يعطي الحوار أولوية بين الطلبات، لكن دفعة المنطقة الواحدة قد تحتفظ بالمحرك لأربع رسائل قبل الرد التالي.

## التنفيذ والتحقق

1. نشر الرسائل السليمة تدريجيًا دون عرض اسم وحده، مع تثبيت تخطيط الصفحة وألوانها وعدم سقوط نتيجة سليمة بسبب خلية متعثرة.
2. تجديد النتائج الموجودة فقط أثناء تأكيد نفس المصدر، ثم مسحها عند اختفائه؛ منع إعادة نتيجة صفحة قديمة فوق صفحة جديدة.
3. تحديد ملكية خلايا الرسائل مكانيًا قبل تأكيد صفحة التتبع، ومنع قراءة الزوايا كحوار GTA VI، دون منع الحوار المركزي أو ردوده القصيرة.
4. تقطيع طلبات المناطق بحيث يستطيع الحوار التقدم بعد الرسالة الحالية. لا تشغيل متزامن عشوائي للمحرك المحلي.
5. اختبارات إعادة إنتاج أولًا، ثم التعديل واختبارات ويندوز والشاشة، ومعاينة العرض. حزمة نهائية واحدة بعد نجاح الاختبارات. حفظ المفاتيح والنماذج والمناطق. تطبيق الهاتف مؤجل حسب القرار السابق.

## نتائج إعادة الإنتاج والتنفيذ

فشلت ست حالات جديدة على 0.5.8 قبل التعديل: ظهور أجزاء سليمة مع جزء مرفوض (الجوال والتنبيه)، تجديدهما، اختلاف OCR للفقاعة ذاتها، وأولوية الحوار داخل دفعة مناطق. بعد التعديل نجحت 66 حالة Core محددة، منها رفض طلب اسم المرسل دون تعطيل الجسم، إزالة النتائج عند اختفاء المصدر، والاستمرار عند فقد قراءة العنوان وبقاء رسالة مؤكدة. الاختبار القديم الذي انتظر كل الصفحة عُدل ليؤكد عرض الجزء الجاهز ثم اكتمال الصفحة دون تبدل مواضعها.

لم يُضف فلتر عامية جديد ولا تغيير للنموذج. لا إعادة ضبط للمناطق أو الخط أو المفاتيح. Windows 0.5.9 هو التحديث التنفيذي؛ TV 0.4.8 الحالي متوافق دون تعديل، ولن يُعاد بناء APK نفسه. التالي تحقق Windows الكامل وصور العرض، ثم تغليف نهائي واحد.

تعذر أول اختبار محلي بسبب امتلاء مساحة البناء؛ أُزيلت مخرجات Debug المولّدة فقط، ثم نُفذت الاختبارات بنمط Release الموجود. لم تُحذف مقاطع المستخدم أو إعداداته أو النماذج.
